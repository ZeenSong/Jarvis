## 当前机器的操作

```bash
cd /home/root2023/Codes/Projects/Jarvis
bash deploy/m2/start.sh prepare
```

需要 sudo 密码，以读取 root 专属 K3s 配置；这是当前生产操作的阻塞点。原 K3s 文件与默认 minikube 配置不变。当前机器的模型参数与独立登录文件已准备好；Codex 固定 `gpt-5.6-luna`，不自动升级模型。

随后按 [启动指导](../deploy/m2/README.md) 执行 `backup`、`deploy`、`pair`。`status` 查看状态，`rollback` 恢复原服务镜像。脚本不会把未执行的集群隔离与真机验证标为通过，剩余项见 [验收记录](../docs/m2/acceptance.md) 与 [双端 Demo](../docs/m2/demo.md)。

迁移到其他机器时，先解压源码，再把镜像包放入源码目录下的 `artifacts/`，运行 `npm ci` 并填写专用凭据路径；不要把旧 refresh token 覆盖到已有续期的登录文件。
