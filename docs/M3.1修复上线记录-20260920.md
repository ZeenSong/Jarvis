## Hermes 在哪里

Jarvis 左侧 **Hermes**，以及首页下方 **Hermes Agent** 卡片。里面的入口打开 Hermes 官方 Dashboard；没有另写一套技能、模型或 MCP 管理页面。

服务器运行：

```bash
cd /home/root2023/Codes/Projects/Jarvis
kubectl --kubeconfig .local/m2.kubeconfig -n jarvis port-forward --address=127.0.0.1 deployment/hermes-core 9119:9119
```

自己电脑另开终端：

```bash
ssh -N -L 9119:127.0.0.1:9119 root2023@100.77.157.73
```

保持两个终端运行，在自己电脑打开 http://127.0.0.1:9119 。控制台只监听 Pod 内回环地址，不直接公开管理界面。临时 port-forward 在 Pod 重建后需重开。

采用官方镜像固定摘要 `sha256:61b5b208cbda39186457116e4d267096bda7f503a135eef1572df3d8df216a7b`，只执行其原生 Web 构建，产物镜像 `jarvis-hermes-dashboard:20260920`。Gateway 与 Dashboard 由镜像自带 s6 管理，共用原有持久卷。Kubernetes Secret 与官方持久化 profile 的 API key 在初始化时同步，避免环境变量和旧 .env 不一致导致 401。清单不再包含会覆盖生产值的占位 Secret。

官方 Dashboard 已实测显示 Gateway Running。上游页面仍把 API server 显示为 Disconnected，且会话筛选显示 0、存储总数非 0；不能用这两个标签代替 Jarvis→Hermes 的认证请求和真实对话结果判断可用性，本次未修改上游 UI。
