# M3.1 implementation checkpoint

This checkpoint records the first integrated M3.1 slice.

## Current Hermes verification (2026-09-16)

The production path now runs `ConversationService -> HermesClient -> Hermes MCP -> Jarvis capability`.
The Core no longer owns a DeepSeek tool schema or a fixed tool loop. A real Tailscale HTTP conversation
successfully called `system_status_read`; a second real conversation called `ui_view_show`, created a
persisted view, and wrote its `view_id` back to the reply. Hermes is reachable by the internal
`hermes-core:8642` ClusterIP only; users access Jarvis at `http://100.77.157.73:8080/home`.
The DeepSeek V4.1-Flash API identifier is `deepseek-flash`; the official API routes that identifier to
the V4.1-Flash release. Detailed evidence is in [hermes-mcp-live.json](evidence/m3.1-20260916/hermes-mcp-live.json).

## Delivered

- Durable `workspace_records`, `workspace_artifacts` and `workspace_bindings` tables. The legacy `workspaces` table remains the short lived Coding Worker checkout model.
- Authenticated `workspace.list/get/create`, artifact upsert and resource binding Gateway topics with monotonic revisions and device ownership checks.
- Web Conversation Markdown rendering for headings, inline code, fenced code, tables and safe external links.
- Web persistent Workspace panel with artifact source editing and sandboxed HTML preview.
- Android Workspace route with persistent workspace discovery and the existing semantic renderer retained for backwards compatible Dynamic UI tests.
- Hermes OpenAI-compatible streaming/tool-call bridge, explicit opt in (`HERMES_ENABLED=1`), internal K3s deployment, PVC, health probes, server-only NetworkPolicy ingress and no public service exposure.
- Hermes Durable Task runtime adapter：`ops-agent` 迁移为只读 Hermes 子智能体运行时；生产 Agent registry 不再注册 Pydantic，旧兼容类仅供显式测试/迁移调用方使用。
- Hermes Ops Tool Bridge：运行时可绑定 Kernel 只读 capability，携带稳定 owner、逐轮执行受控 tool calls，并发出 `agent.tool.*` 生命周期事件；禁止 shell/写入能力。
- App Bridge link resolution and Ubuntu first Node Bridge capability/registration contracts.
- Identity 基础：Argon2id 用户凭据、旧设备认领管理员 bootstrap、登录/刷新/会话列表/撤销 API；Access 15 分钟、Refresh 30 天轮换。
- Web 登录会话会在页面重启时自动使用 HttpOnly Refresh Cookie 恢复，并提供退出接口。
- Android 登录页支持用户名/密码；Access/Refresh Token 均以 Android Keystore AES-GCM 加密后保存于 DataStore，会话失效时自动轮换并重连。
- Control Plane 基础：持久化 Approval、Notification、Schedule；支持一次性/每日/每周调度、启停删除和到期自动创建会话消息。
- AgentManager 遇到 `agent.approval.required` 时自动生成持久化 Approval/Notification；同一 Run/Capability 的重复事件幂等，批准后恢复对应 Runtime，拒绝或重复消费会被拒绝。
- Artifact 安全校验：拒绝 iframe/object/embed、动态代码逃逸和网络调用，并在 iframe 中附加 CSP 与 `sandbox`。
- Ubuntu Node Bridge runtime：WebSocket 注册/心跳、localhost health/capability 端点，以及受授权根目录限制的系统/文件读取执行端点。
- Node Bridge invocation：Kernel `node.invoke` 按节点归属与已注册 capability 校验，通过认证 WebSocket 请求 Node 执行；运行时提供受限的系统/文件读取与 `git status`，配置 `NODE_CODEX_BIN` 后才广播 Codex execute；高风险 capability 必须匹配已批准的 Approval。
- Node Bridge ownership claim：登录用户可通过 `agent.claim` 认领已配对节点，随后同一用户的多设备共享该节点能力，未认领节点仍拒绝跨设备调用。
- 任务、运行实例、运行快照和 LLM 用量查询增加 owner 过滤；运行快照不再写入全局资源广播，避免跨用户泄漏。
- Conversation、Conversation Message、Durable Task/Run、Workspace、View、Approval、Notification、Schedule 现同时保存稳定 `owner_user_id`（兼容旧设备归属并在迁移时回填），同一用户的多设备会话可共享这些对象。
- Gateway 增加版本化 `capability.list` / `mcp.catalog.list`，公开能力类型、风险和审批要求，执行仍由 Kernel 权限层控制。
- 新增版本化 Capability Registry：可通过受控 `MCP_CATALOG_JSON` 注入外部 MCP provider 元数据并与内置能力合并；同时提供 `task.*` 兼容入口，逐步将旧 `agent.run.*` 迁移到 Durable Task 语义。
- Durable Task 绑定：Run 可关联用户 Workspace，Workspace `task_id` 校验同一用户/Conversation，Task Scheduler 覆盖 Hermes runtime；AgentManager 同时导出 `TaskManager` / `ExecutionManager` 迁移别名。
- Approval 与 Task 绑定：approval 的 `run_id` 在历史数据无孤儿时自动建立外键（删除任务置空），并增加按 Run/状态索引；旧不一致数据保持可读并由应用层拒绝越权。
- Agent Registry 的列表、详情与事件 API 也按用户/设备归属过滤，节点记录同步保存 `owner_user_id`。
- Web 控制面面板：展示通知与待审批事项，可直接批准/拒绝并标记通知已读。
- Web 控制面支持创建、启停、删除一次性/每日/每周 Schedule，并显示下次运行时间。
- Gateway 事件补齐 `conversation.tool.*`、`conversation.status`、`task.*` 与 `workspace.opened`，Web/Android 可观察同一执行生命周期。
- Web / Android 应用详情：通过 `app.resolve` 解析统一 Deep Link，按平台回退到安全网页地址。
- 管理员成员邀请 UI：控制面板读取当前身份，管理员可生成 7 天一次性成员邀请令牌。
- Web 成员邀请接受端：输入令牌与新密码后原子创建成员并自动登录。
- Web 控制面同时列出已登录设备/浏览器，并支持主动撤销单个 Session。
- Integration Credential 边界：独立 `integration_credentials` 表按用户归属，AES-256-GCM 加密 provider secret；Gateway 只返回 provider/label/metadata，缺少 `INTEGRATION_CREDENTIAL_KEY`（32-byte base64url）时拒绝写入。
