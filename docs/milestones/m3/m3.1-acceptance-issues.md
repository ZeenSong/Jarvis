## 3. 问题与修改意见

### Q01 · P0 · 生产 Hermes 无推理 provider，空回复被误报成功（已修复，真实链路已复验）

- 复现：生产 Web → Jarvis → 新会话 → 发送“请调用工具读取服务器状态，以 Markdown 二级标题、加粗文字、两列表格和一个只读示例代码块给出简短结果，并展示系统状态图表。请勿修改系统。”
- 实际：同日真实生产会话约 6 秒后显示“Jarvis · 已完成 / 正在处理…”，无正文、无图表、无 tool 事件，只有两条 conversation.status 事件。本轮重跑时已有浏览器 state 已过期，`live-fatal.png` 记录实际落到登录页。
- 根因证据：Hermes 日志明确 `No inference provider configured`；直接从 Gateway Pod 请求 Hermes 返回 HTTP 200 SSE，但仅 role/stop/[DONE]，prompt/completion tokens 均为 0。health=true 不代表模型可用。
- 修复结果：已配置官方 DeepSeek provider、MCP provider 与桥接密钥；DeepSeek V4.1-Flash 按官方 API 标识 `deepseek-flash` 调用；真实 status/view 对话均有正文和工具结果，空 provider 不再静默回退。当前证据见 [Hermes MCP 真实链路](../../evidence/m3.1-20260916/hermes-mcp-live.json)。
- 证据：[真实对话截图](../../evidence/m3.1-20260916/15-live-conversation.png)、[本轮登录态现场](../../evidence/m3.1-20260916/live-fatal.png)、[事件](../../evidence/m3.1-20260916/live-results.json)、[Hermes 日志](../../evidence/m3.1-20260916/hermes-provider-error.txt)、[原始 SSE](../../evidence/m3.1-20260916/hermes-wire.json)。

### Q02 · P1 · Web“新建工作区”导致整页空白（已修复）

- 已修复。`workspace.create` 返回的平铺对象现在会被显式规范化，创建后重新读取当前 Workspace 并加入列表；选择与保存也不会把未定义对象写入 React 状态。已通过 `npm run typecheck` 与 Web production build。

### Q03 · P1 · Web Refresh Cookie 截断错误，Access 到期掉登录（已修复并通过生产回归）

- 已修复并通过生产回归。Refresh 现在使用统一 Cookie 解析，不再依赖错误的固定 slice；真实 Access 过期后 Cookie refresh 返回 200。

### Q04 · P0 · 撤销 Session 不撤销已有 WebSocket 权限（已修复并通过生产回归）

- 已修复并通过生产回归。WebSocket 握手保存 `session_id`，单 Session 撤销已关闭撤销前建立的连接，close code 为 4001 `session_revoked`，后续 API 返回 401。

### Q05 · P1 · Android 未实现 Markdown / Code / Table / Link 渲染（已修复并复验）

- 已修复并复验。Android 已加入安全的 Markdown block/inline renderer，覆盖标题、粗斜体、链接、引用、列表、代码块和可横向滚动表格；同时修复了内联正则缺少闭合括号导致的进入对话崩溃。最新 APK 已进入对话并发送短消息，见 `71`–`73` 与 `android-crash-before-fix.txt`。

### Q06 · P2 · Web Markdown 只实现了部分语法（已修复）

- 已修复。Web renderer 已覆盖标题、粗斜体、HTTPS 链接、引用、列表、代码块和表格，并只允许 HTTPS 外链。

### Q07 · P1 · Conversation ↔ Workspace / Rich Message 尚未形成完整体验

- 主链路已完成。Web 保持 conversation-list、chat、workspace-side 同屏；Android “打开工作区”导航到 Workspace，并优先渲染持久化 compiled Artifact。真实回复携带稳定 `workspace_id`/`view_id`，Tool 状态显示为小卡片；完整 Rich Component 和全部 Artifact 类型属于后续扩展，不是本轮 M3.1 阻塞项。

### Q08 · P1 · 生产 App Bridge 无可用 launch / deep link（已修复并复验）

- 已修复并复验。生产已配置 Home Assistant `http://100.77.157.73:8123` 与 Immich `http://100.77.157.73:2283`；实时 `app.resolve` 已返回 Immich album 与 Home Assistant entity 的资源级链接，应用页也提供“让 Jarvis 分析此应用”AI Action；最新 APK 已在 Chrome 打开 Immich URL 并收到目标服务响应，见 `74-android-deeplink.png`。

### Q09 · P1 · Hermes 迁移仍是兼容接口包装，Core/Agent 边界未完成

- 修复结果：`ConversationService` 现在只拼接受控上下文并调用 Hermes 一次，不再声明 DeepSeek 工具、不再维护 Core 工具轮询或静默回退；Hermes MCP 负责工具发现、执行和结果回填。
- Core 的 MCP context token 绑定设备与会话并带 HMAC/过期时间；Jarvis 内部 capability endpoint 只允许白名单能力，并发出 `conversation.tool.*` 事件。
- `HermesRuntime` 的本地 bridge 仅保留嵌入式测试适配路径；生产注册不绑定该 bridge。生产真实 Core → Hermes → MCP → Capability 证据见 `hermes-mcp-live.json`。
- 尚需在实体 Tailnet Android 设备上复验 App 资源页；Hermes 临时 delegation 的重启行为按持久化任务边界处理，不静默重放副作用。第 35 节将所有 Workspace 类型列为非目标，不作为本轮阻塞项。

### Q10 · P1 · Codex 的 Node Capability 未在目标节点落地（已修复）

- 已修复。Ubuntu Node Bridge 当前广播 `node.codex.execute`，Codex 运行在项目只读挂载的容器中，cwd 受 `/workspace` 限制，执行需要审批。现场 HTTP 验收链路返回 200、`exit_code=0`、stdout=`OK`，见 [Node Codex 真实证据](../../evidence/m3.1-20260916/node-codex-live.json)。

### Q11 · P2 · Workspace 编辑器跨对象保留旧源码，保存行为不是原 Artifact 更新（已修复）

- 已修复。Workspace 切换时编辑源会按当前 Artifact 同步；upsert 会传递现有 `artifact_id`，因此同一 Artifact 更新而不是每次新建。

### Q12 · P2 · 已登录设备无法辨认具体终端（已修复并复验）

- 已修复并复验。Web 首次登录生成并持久化浏览器 UUID，Android 登录生成设备 UUID，服务端按显式 `device_id` 注册/绑定 Session；控制面板可列出两台新设备，见 `f7-sessions-current.png`、`auth-sessions-live.json`。
