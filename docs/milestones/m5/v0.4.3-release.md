# Jarvis v0.4.3 — 更快的语音、图片理解与 DSH 开发工作台

版本：`v0.4.3`  
Android：`versionCode 8` / `versionName 0.4.3`  
基线：`v0.4.2`

## 语音更快了

- 自建 Whisper 从 `large-v3` 切换到 `large-v3-turbo`：同一条 8 秒中文样本，热态转写从 **2.30 秒降到 0.60 秒**；经 Jarvis 接口实测 **0.79 秒**。
- 云端录音增加静音断句：说完后停顿约 0.8 秒自动提交，不必再找“停止”按钮；最长仍为 30 秒。
- 点击录音时若 Jarvis 还在播报，会先打断当前 TTS，避免把自己的声音录进去。
- 华为等无 GMS 设备的问候语缩短为“我在，点下方按钮说话”，可以更快开始第一轮。
- 系统识别不可用、语言包不支持、连续错误、长时间无结果时都会自动切到云端识别，不再卡在“正在聆听”。

## 图片上传与理解

- Web 与 Android 对话输入区都支持选择图片（PNG/JPEG/WebP，单张≤2 MB；Web 最多 4 张，Android 单张）。
- 图片存入会话级 `media_resources`，消息里只携带 `MEDIA_RESOURCE:<id>`，历史记录和断线恢复不依赖本地文件。
- 服务端在交给 Hermes 之前，先用当前多模态模型（`deepseek-flash`）生成图片描述并转写图中文字，再和用户问题一起送入原任务流；图片中的文字被当作不可信数据，不能覆盖系统指令。
- 图片不会写入对话文本、不会进入模型上下文之外的第三方服务；客户端通过带登录态的 `/api/media/<id>/content` 读取。
- 实测：Android 选择一张登录页截图并问“What is in this image?”，Jarvis 准确描述了金色球体、登录表单和底部标语；iOS/Android 之外的 Web 也使用同一接口和渲染器。

## DeepSeek Harness 成为默认开发工具

- 新增 `DshRuntime`：以 `dsh --profile headless --json` 运行，将 thinking、tool_call、tool_result、usage、final 映射为 Jarvis 的 Agent 事件。
- `coding-agent` 默认 runtime 从不可用的 `codex` 改为 `dsh`，新迁移 `0008-dsh-coding-agent` 幂等更新已有数据库。
- 容器内提供 `dsh` 二进制；`DSH_HOME` 持久化 profile/session，`DSH_WORKSPACE` 挂载代码目录，`DEEPSEEK_API_KEY` 提供模型凭据。
- 实测任务：DSH 在当前 workspace 创建 `dsh-task-output.txt`，内容 `DSH_TASK_OK`，Jarvis 任务状态 `completed`，摘要 `DSH_TASK_OK`，执行约 4 秒（不含模型排队）。
- Jarvis 继续使用自己的容器权限边界（只读 rootfs、`cap_drop: ALL`、`no-new-privileges`）；DSH 只能写显式挂载的 workspace/home。

## 已知限制

- 图片理解依赖 `deepseek-flash` 的多模态能力；如果切换到纯文本模型，服务端会保留图片但视觉理解会失败并给出提示。
- 云端语音仍是“点一下开始，停顿自动发送”，不是全双工流式 ASR；首轮冷启动（Whisper 模型未加载）约 20–40 秒，预热后 1 秒内。
- DSH 任务运行在容器内的 workspace，Android SDK 等宿主机工具不一定可用；需要完整 Android 构建时仍应在开发机执行。
- Debug APK 适合自托管与侧载，不是 Google Play 生产签名。
